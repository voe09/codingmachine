# #moe

Archive coverage: 2025-04-29–2026-09-19 (UTC); 1,734 messages, including 559 thread replies. [Open channel in Discord](https://discord.com/channels/1354881461060243556/1365044508546568372).

## Discussion and lessons

- MoE work established iterative iso-FLOP baselines, routing and initialization ablations, load balancing, learning-rate schedule comparisons, and large-run scaling. The stated process was to promote a change only after it beats the current baseline under comparable conditions. [Source](https://marin-discord.pages.dev/#1365044508546568372/1481488141012697190).
- At 3e18 FLOPs, a linear-decay schedule lowered reported BPB from 1.047 to 1.016. QB load balancing then allowed expert padding to fall from 0.25x to zero with a reported 10–15% speedup and negligible BPB difference. These are configuration-specific results. [Schedule](https://marin-discord.pages.dev/#1365044508546568372/1485898126454820907); [load balancing](https://marin-discord.pages.dev/#1365044508546568372/1487197835580412055).
- MuonH showed roughly 20–30% step-count improvement versus AdamH in a reported sweep, but hardware efficiency and scale remained separate questions. [Source](https://marin-discord.pages.dev/#1365044508546568372/1502824423936491550).
- Router vectors in one large run became strongly aligned, motivating investigation of whether this helped or hurt specialization. A later d768 ladder test showed router-metric excursions with the responsible change not yet isolated. [Router analysis](https://marin-discord.pages.dev/#1365044508546568372/1489131651920564244); [open investigation](https://marin-discord.pages.dev/#1365044508546568372/1550547629958504620).
- MoE evaluation used more than loss: the proposed baseline gate considered routing stability, training stability, and hardware FLOPs to a loss target. A 1e21-FLOP iteration predicted uncheatable macro loss of 1.8324, but prediction quality remained a separate concern. [Discussion](https://marin-discord.pages.dev/#1365044508546568372/1482069994643783991).
- A kernel comparison found grouped matrix multiplication faster than ragged dot in its tested setting. Larger top-k hurt throughput, while a shared expert helped; these systems costs matter when comparing architectures at fixed wall-clock budget. [Discussion](https://marin-discord.pages.dev/#1365044508546568372/1470278088041562346).
- One apparent QB throughput improvement was invalid: QB had accidentally been moved outside the timing harness. The team corrected the benchmark before interpreting the load-balancing result. [Discussion](https://marin-discord.pages.dev/#1365044508546568372/1485443721788129340).
- A first Muon configuration improved in-domain training but regressed on out-of-domain code loss (GitHub/C++ 2.55 versus 2.2 for AdamH). Keeping AdamH on the language-model head in a later MuonH variant addressed the regression in a small sweep; this is why optimizer claims need per-domain evaluation. [Initial regression](https://marin-discord.pages.dev/#1365044508546568372/1502491222105915472); [MuonH result](https://marin-discord.pages.dev/#1365044508546568372/1502824423936491550).
- A routing imbalance was not automatically classified as expert collapse: two layer-3 experts took about 70% of load, and participants noted that a Zipfian token distribution can make perfectly uniform routing an inappropriate target. [Discussion](https://marin-discord.pages.dev/#1365044508546568372/1489356958967398480).
