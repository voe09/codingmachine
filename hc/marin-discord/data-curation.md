# #data-curation

Archive coverage: 2025-05-15–2026-09-22 (UTC); 903 messages, including 390 thread replies. [Open channel in Discord](https://discord.com/channels/1354881461060243556/1368297424086499359).

## Open data and synthetic reasoning

The channel connects dataset licenses, generation cost, teacher quality, and the training stage where a corpus is used. One proposed open-data program estimated that roughly 5T openly licensed tokens might be attainable through synthetic augmentation; that was a feasibility claim, not an assembled corpus. Rewriting also consumes compute, so its value has to be compared with training longer on existing text at the same budget. The release workflow kept separate data cards for corpora and linked them from the model card. [Open-data proposal](https://marin-discord.pages.dev/#1368297424086499359/1437529815665213480); [rewrite-cost warning](https://marin-discord.pages.dev/#1368297424086499359/1385003698606051358); [data cards](https://marin-discord.pages.dev/#1368297424086499359/1373033396997193890).

The OpenThoughts/LAION collaboration used large-scale generation to investigate reasoning-data design. The LAION group reported using 150,000 H100 hours to create a 32k-output code set with Qwen3-32B. A controlled question was whether 7k versus 32k response caps changed student performance enough to justify generating equally long math and science sets. The archive records those training comparisons being launched, not a final universal answer about optimal trace length. [Generation scale](https://marin-discord.pages.dev/#1368297424086499359/1446386279913750681); [length comparison](https://marin-discord.pages.dev/#1368297424086499359/1451566186679505123).

Teacher comparisons were similarly controlled: 30,000 OpenThoughts4 math prompts were answered by Qwen3-32B and Qwen3-235B-A22B at 16k sequence length, then used to fine-tune the same Qwen2.5-7B-Instruct student. Sampling unique prompt IDs mattered because a teacher-quality comparison would be confounded by duplicate prompts. A later rejection-sampling experiment drew eight responses from Qwen3-4B and retained one whose final answer matched Qwen3-32B. It modestly beat training on a random 4B response or a 32B response alone for the tested 1.7B student. This does not imply the smaller teacher is generally better; selection and student alignment are part of the result. [Teacher plan](https://marin-discord.pages.dev/#1368297424086499359/1458524762090242179); [prompt sampling](https://marin-discord.pages.dev/#1461252391570768036/1463348302836666533); [rejection-sampling result](https://marin-discord.pages.dev/#1368297424086499359/1476381841345744961).

Generated data can fail before a model learns from it. Some GLM outputs contained malformed thinking blocks; the vLLM reasoning parser changed whether those blocks were correctly interpreted, and template mismatches could affect 1–3% of samples in one account. The group also questioned whether math corpora emphasizing hard web-mined problems supplied enough basic arithmetic for agent rollouts. Both are reasons to inspect examples and task-specific errors before simply scaling generation volume. [Parser and template failures](https://marin-discord.pages.dev/#1368297424086499359/1478196842285236234); [arithmetic concern](https://marin-discord.pages.dev/#1368297424086499359/1486977555842994246).

## Agent trajectories and verifiers

SWE-ZERO began with 1,000 trajectories across ten SWE-rebench repositories. Under its stated Jaccard threshold, 87.4% of bash commands were unique, and its mini-coder teacher reportedly exceeded 50% SWE-Bench pass@100. This established a generation pipeline and a diversity check; it did not demonstrate that a planned 100B-token dataset would improve a trained student. [SWE-ZERO report](https://marin-discord.pages.dev/#1368297424086499359/1492293100058706011).

TaskTrove exposed a different bottleneck: 43 potentially useful Harbor-format datasets lacked verifiers. Some had ground-truth tests that had not been packaged; others would need an LLM judge. The channel recommended separating deterministic RL-verifiable tasks from judged tasks because reward noise and task-specification errors differ. A proposed task-selection heuristic sought a large pass@16-to-pass@1 gap for the student while a stronger model could still solve the task, but the author labeled this a working hypothesis. [Verifier backlog](https://marin-discord.pages.dev/#1368297424086499359/1529499435321790555); [reward-gap hypothesis](https://marin-discord.pages.dev/#1368297424086499359/1544012302431420416); [verifier design](https://marin-discord.pages.dev/#1545689065347620955/1547046085799976960).

A September QASPER audit found that 49.51% of 10,000 tasks lacked the paper the agent was supposed to read, and 74.07% were `_copyN` duplicates of agent-visible questions and instructions. Even when a paper was present, the GPT-4o-mini grader had no gold answer or evidence spans and had to independently solve the question before judging the candidate. The audit challenged whether its reward represented reading comprehension at all. Task count, reward gap, and a judge API were inadequate quality checks without artifact availability, deduplication, and verifier validity. [QASPER audit](https://marin-discord.pages.dev/#1368297424086499359/1545689065347620955).

Contamination checks needed the same care. An initial SFT-data audit flagged KernelGym examples against Terminal-Bench because both contained ordinary PyTorch import boilerplate. Matching an n-gram is not enough to call a task leaked; the matched span, problem statement, and solution context matter. [Initial audit](https://marin-discord.pages.dev/#1368297424086499359/1549916057580474409); [false-positive example](https://marin-discord.pages.dev/#1368297424086499359/1549917870551466135).
