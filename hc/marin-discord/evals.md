## What should be measured?

The early evaluation suite mixed base-model log-probability tasks with instruction, reasoning, code, preference, and safety benchmarks. A recurring concern was that a fixed multiple-choice score combines capability with domain exposure, test contamination, prompt format, and answer extraction. In September 2025, the group proposed fresh high-quality text from arXiv, GitHub, and news for a broad perplexity measure called “uncheatable.” An initial analysis found better correlation with several downstream benchmarks than Paloma or C4 on its fitted model set, but the author noted that model selection and fitting could explain part of the result. Fresh text is a useful diagnostic, not a proven single measure of intelligence. [Motivation](https://marin-discord.pages.dev/#1356487738840318002/1417394447129382943); [correlation check](https://marin-discord.pages.dev/#1356487738840318002/1418685458988269569).

The 32B base-model comparison used 32 selected tasks and reported mean per-dataset ranks of Marin 2.38, OLMo-2-32B 2.75, Qwen2.5-32B 2.19, and Gemma-3-27B-PT 2.59 under that suite. Other discussion identified persistent gaps in MMLU, BBH, coding, and some reasoning and safety tasks. These observations should be read with the exact task versions and training stages: the group also objected to comparing a model without midtraining to one that had received it. [32-task comparison](https://marin-discord.pages.dev/#1356487738840318002/1435383466408808580); [gap analysis](https://marin-discord.pages.dev/#1356487738840318002/1441587733918257264); [stage-matching concern](https://marin-discord.pages.dev/#1356487738840318002/1507184887084482671).

Some proxies failed. A February 2026 sweep found poor correlation between MATH accuracy and BPB on model-generated reasoning traces, so its author planned to repeat after SFT. The lesson is to test a proposed proxy against the capability it is meant to predict, including the relevant training stage, rather than treating lower loss on any plausible text as sufficient. [Reasoning-trace test](https://marin-discord.pages.dev/#1356487738840318002/1470224087426138246).

## Evaluation code is part of the result

An AIME run looked weak partly because its chat template was applied incorrectly, then because exact-match grading did not extract the mathematical answer. Correcting the model-evaluation interface changed what the score meant without changing weights. Serving details such as stop conditions and tokenization have similar effects. The channel repeatedly favored saved prompts, outputs, and versioned task definitions so a surprising score can be inspected. [AIME failure analysis](https://marin-discord.pages.dev/#1356487738840318002/1427789130460561528); [benchmark-version guidance](https://marin-discord.pages.dev/#1528226796729008288/1529535129498685471).

The framework discussion sought one route for pretraining log-probability and generation tasks, with environment-based evaluation for post-training agents. `lm-evaluation-harness` covered the former; Evalchemy and a Harbor-style environment interface were considered for the latter. New tasks such as AIME26, OlympiadBench, long-context coding, and agentic benchmarks required maintained adapters and graders. A corrected benchmark should remain separately accessible from its historical version, because silently replacing an erroneous definition would make old scores uninterpretable. [Common-stack proposal](https://marin-discord.pages.dev/#1356487738840318002/1461766966040596644); [Evalchemy trade-off](https://marin-discord.pages.dev/#1356487738840318002/1463309011624398880); [new task work](https://marin-discord.pages.dev/#1356487738840318002/1478312632279765065); [versioning proposal](https://marin-discord.pages.dev/#1528226796729008288/1529535129498685471).

By September 2026, the agent-evaluation stack raised a harder comparability problem. Harbor training fixes, including changes to continuation tokenization, could make the current training environment differ from a pinned Terminal-Bench evaluation. The proposed response was to measure the impact and possibly maintain two lanes: a frozen protocol for cross-model comparison and a current-stack protocol for selecting checkpoints. If they differ, reports should name both protocols and the result under each. This was a proposal pending the comparison test. [Mismatch report](https://marin-discord.pages.dev/#1356487738840318002/1547681351849869486); [two-lane proposal](https://marin-discord.pages.dev/#1356487738840318002/1547710721259868220).

Evaluation also became a data-development tool. A later analysis found Marin weak at coding, reading tool results, and patch construction despite smoother MoE training, motivating targeted data work rather than another architecture tweak. For small proxy models, researchers explored easier variants of hard tasks and stronger-model reranking to avoid floor scores. These were ways to make an evaluation sensitive enough to guide the next experiment, not reported fixes for the capability gap. [Capability diagnosis](https://marin-discord.pages.dev/#1356487738840318002/1498186408530149426); [weak-model proxy idea](https://marin-discord.pages.dev/#1356487738840318002/1498467472276197527).
