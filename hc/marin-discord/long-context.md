# #long-context

Archive coverage: 2025-06-08–2026-09-22 (UTC); 293 messages, including 72 thread replies. [Open channel in Discord](https://discord.com/channels/1354881461060243556/1380235124011958313).

## Target behavior and early baselines

The immediate long-context target was agentic work over repositories: following information across files and tool calls, not merely reading a single long document. The group proposed first evaluating the existing Marin 8B Instruct checkpoint, then testing SWE-Smith fine-tuning, before changing positional encodings such as YaRN. An early SWE-Smith fine-tune resolved 14 of 500 SWE-Bench Verified issues, establishing a nonzero agentic baseline but not isolating context extension as the cause. [Research sequence](https://marin-discord.pages.dev/#1380235124011958313/1394527166674243606) · [Agentic baseline](https://marin-discord.pages.dev/#1380235124011958313/1396039727081324644).

The data hypothesis was that code understanding often needs several files together even though each individual file fits in a short window. The team prepared concatenated repositories, initially with random within-repo ordering, while considering topology-aware ordering as a later experiment. Linear-attention alternatives such as BASED and Minimax were discussed, but participants noted that a naive implementation would likely lose to optimized Transformer kernels; an efficient TPU kernel would be necessary to realize the advertised savings. [Repository data](https://marin-discord.pages.dev/#1397996868503605308/1398070439162413098) · [Linear-attention implementation](https://marin-discord.pages.dev/#1380235124011958313/1381410617524748318).

## Extension stages, cost, and evaluation

A later 8B adaptation stage stayed at 4k context while mixing 90% cooldown data with 5% PDF text and 5% reasoning/SFT data. The first attempt used an unintended lower learning rate, so the corrected run was the relevant comparison. A subsequent loss report found large PDF gains with relatively small Paloma degradation, but generation-based long-context evaluation was still needed to establish usable behavior. [Adaptation recipe](https://marin-discord.pages.dev/#1380235124011958313/1448056067761373316) · [Loss report](https://marin-discord.pages.dev/#1380235124011958313/1450407018971009054).

For the larger MoE program, the proposed smaller-model ablations compared 4k→4k, 4k→32k, 8k→32k, and 8k→64k schedules before taking a 32k/64k model toward 262k. The final phase was expected to be a small fraction of total tokens but still expensive. In a later discussion, 1T tokens at 65k was justified partly by measured throughput: about 30% slower in tokens/s during the last 10% of training, or roughly 4% extra total runtime. The team explicitly lacked clean scaling laws showing whether 0.5T or 2T would be better. [Planned ablations](https://marin-discord.pages.dev/#1380235124011958313/1516509704535281666) · [65k cost reasoning](https://marin-discord.pages.dev/#1380235124011958313/1551872818051022859).

The data and eval ideas evolved toward *interleaved medium-length documents*. Riffle-interleaving related chunks could simulate retrieving an earlier thread of context amid distractions and reduce reliance on rare, distribution-shifting naturally long documents. RiffleEval proposed asking the model to predict a document after such interleaving, optionally without explicit document IDs. These were proposals to test state tracking and cross-document attention, not reported proof of a model gain. [Riffle-data idea](https://marin-discord.pages.dev/#1380235124011958313/1507525581699285044) · [RiffleEval design](https://marin-discord.pages.dev/#1380235124011958313/1543017917124313278).
