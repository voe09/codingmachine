# #ideas

Archive coverage: 2025-05-26–2026-09-16 (UTC); 44 messages. Every exported message body in this channel was reviewed. [Open channel in Discord](https://discord.com/channels/1354881461060243556/1376621616531902554).

This channel is mostly a proposal queue, so the distinction between a lead and a Marin result matters. A cited Mamba training account argued that early sequence tokens are close to unconditional prediction while later tokens can exploit context. Position-weighting the loss reportedly improved top-k validation but not perplexity in that external account, illustrating that metrics weight token positions differently; Marin did not report a local position-weighting test here. The same external write-up compared WSD and cosine schedules on the same model/data and attributed WSD-only loss spikes to holding the peak learning rate too long, rather than immediately blaming bad batches. These are literature leads for controlled ablations, not a Marin diagnosis. [Position-weighting lead](https://marin-discord.pages.dev/#1376621616531902554/1378121127804797088) · [Schedule lead](https://marin-discord.pages.dev/#1376621616531902554/1378122104184115321).

Data ideas included training on a broader selection of Hugging Face datasets **after decontamination** and using an LLM to inspect unfamiliar SFT schemas, choose a transform template, and write the download/format/tokenization code. A bottleneck remained how to cheaply decide which dataset is worth training on: the reliable ISO-FLOP scaling-law ablation was considered expensive, and participants proposed finding the smallest sampled experiment that still estimates a dataset's scaling slope. They had observed that compute-optimal settings can depend on the data, so one universal proxy configuration might mis-rank datasets. [Broad-data proposal](https://marin-discord.pages.dev/#1376621616531902554/1394895344978100294) · [SFT ingestion automation](https://marin-discord.pages.dev/#1376621616531902554/1398192151677894717) · [Ablation cost](https://marin-discord.pages.dev/#1376621616531902554/1414655979156406312) · [Data-dependent optimum](https://marin-discord.pages.dev/#1376621616531902554/1414656659015336006).

An architecture suggestion was to run distinct Marin-8B midtraining cooldowns, then use those specialized checkpoints as MoE experts rather than copy one checkpoint into all experts. This remained an idea in this channel. Parallel attention and MLP/feedforward execution did reach a small-scale speedrun: although an external contributor reported favorable larger-scale experience, the Marin test was said to **underperform the small “hackable” baseline**, with a trend that might improve at larger scales. Participants called for ISO-FLOP comparison and questioned whether the sparse plotted points justified extrapolating a crossover. A small-scale loss is therefore neither proof the architecture fails everywhere nor evidence that it will win at scale. [Specialized-expert idea](https://marin-discord.pages.dev/#1376621616531902554/1415044075186557069) · [Parallel-block proposal](https://marin-discord.pages.dev/#1376621616531902554/1415068848679424050) · [Speedrun result](https://marin-discord.pages.dev/#1376621616531902554/1438673150647992382) · [Extrapolation caution](https://marin-discord.pages.dev/#1376621616531902554/1438697533714202694).
