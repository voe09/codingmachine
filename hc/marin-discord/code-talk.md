## Repository and experiment architecture

The 2025 monorepo move brought Marin experiments, the Marin library, and Levanter into a single `uv` workspace. That reduced cross-repository coordination but raised a design question: reusable defaults and evaluation task configuration might belong in an importable library, while individual experiments should remain project-specific. A proposed audio integration tested whether Marin could work as a library for projects outside the main tree. [Migration notice](https://marin-discord.pages.dev/#1366632114316906506/1435085750231240714) · [Library boundary](https://marin-discord.pages.dev/#1366632114316906506/1438699674176323604).

Dependency and configuration semantics remained important. The group preferred rejecting unknown configuration fields to silently ignoring misspellings when discussing a Pydantic-backed Draccus. Hugging Face API rate limits motivated downloading model dependencies sequentially instead of launching a wide sweep that fetched them all at once. A permutation-based shuffle waits for dataset length and thus for tokenization to finish; omitting shuffle can start sooner only when a pre-shuffled input is acceptable. [Strict configuration](https://marin-discord.pages.dev/#1366632114316906506/1423027011101921472) · [Sequential downloads](https://marin-discord.pages.dev/#1422481366137966606/1422630901765898361) · [Shuffle dependency](https://marin-discord.pages.dev/#1366632114316906506/1387330303026004010).

The team increasingly treated reproducibility as a boundary between code and external state: a Git commit identifies local code, while an experiment or artifact revision should capture datasets, tokenizers, and other external inputs that a commit cannot. An explicit revision makes a downstream experiment depend on a particular artifact instead of whichever version happens to be current. This is a design discussion, not a claim that every experiment was already pinned. [Hashing model](https://marin-discord.pages.dev/#1366632114316906506/1487153518526857327) · [Artifact revisions](https://marin-discord.pages.dev/#1366632114316906506/1487282435266711625).

## Silent failures and operational lessons

One serious vLLM bug caused Llama 3 checkpoints to be interpreted as Mistral. For contexts over 4,096 tokens, a sliding window then masked earlier tokens without an obvious load-time failure. Deleting and re-downloading affected model artifacts was the verified immediate repair; a maintained inference fork and stronger end-to-end tests were proposed as longer-term safeguards. The lesson is that checkpoint identity and effective attention masks need behavioral tests, not only successful deserialization. [Bug report](https://marin-discord.pages.dev/#1366632114316906506/1489495767130443857).

Storage and execution choices also had non-obvious costs. A deeply nested ExecutorStep DAG could exhaust memory on the head node. Moving from a default full permutation to block shuffle reportedly cut GCS read counts by at least about 90% with no observed quality degradation in the tests cited, though that remains a workload-specific result. The team wanted to reduce dependence on `gcsfuse` because of stability and multi-cloud portability concerns. [DAG memory](https://marin-discord.pages.dev/#1366632114316906506/1469562031974780989) · [Block shuffle](https://marin-discord.pages.dev/#1366632114316906506/1477097197815468053) · [GCSFuse concern](https://marin-discord.pages.dev/#1366632114316906506/1458726386046074913).

Iris scheduling discussions exposed fairness and location coupling: long-lived parent inference launchers could make new child jobs inherit an old queue timestamp, while pinning data and compute to a region avoided accidental cross-region data movement but reduced scheduling flexibility. Separating data generation from model jobs was proposed to loosen those pins. [Queue-age issue](https://marin-discord.pages.dev/#1366632114316906506/1504196730621526116) · [Region tradeoff](https://marin-discord.pages.dev/#1366632114316906506/1511750771425808424).

Checkpoint names also required a one-step semantics fix: intermediate `step-{kN}` files had been written after `kN+1` steps, while final files used `step-{T-1}` after `T` steps. A proposed change named checkpoints by steps actually trained; keeping metadata-based resume intact mattered more than preserving the misleading filename convention. [Checkpoint-numbering change](https://marin-discord.pages.dev/#1366632114316906506/1529543677754605569).
