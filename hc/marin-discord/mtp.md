## What the channel was trying to connect

The channel began as a place to connect multi-token prediction (MTP) work to the Snowball model. Contributors pointed to earlier Marin MTP exploration and to separate reports on Snowball pretraining, long-context extension, SFT, evaluation, and RL. These links are pointers to the experimental record, not results restated in Discord. The discussion did not establish a Snowball MTP training result. [Earlier MTP work](https://marin-discord.pages.dev/#1546528166086967306/1546532687907655690); [Snowball reports](https://marin-discord.pages.dev/#1546528166086967306/1546529637813854248).

One reproducibility question was what data Snowball had actually seen. A contributor first assembled a coarse source-attribution view from data-mix records, then released a best-effort mapping from the training stream back to Hugging Face source rows without re-hosting the data. The author explicitly asked others to check it. A reply supplied the source list at the run's pinned code revision and the repository procedure for triggering source processing, clarifying that a main-branch source list could differ from the run's list. The useful distinction is source-level attribution versus an exact, verified token-by-token replay: this Discord exchange did not independently validate the latter. [Coarse mapping](https://marin-discord.pages.dev/#1546528166086967306/1546553221240197243); [best-effort replay](https://marin-discord.pages.dev/#1546528166086967306/1547185020102516848); [pinned source list](https://marin-discord.pages.dev/#1547185020102516848/1547277659791425567); [processing procedure](https://marin-discord.pages.dev/#1547185020102516848/1547278202068541491).

## Speculative decoding during RL

The most concrete result in the channel concerned EAGLE-3 speculative decoding, which is related to but distinct from training the base model with an MTP objective. A draft model proposes tokens and the target model accepts or rejects them, potentially reducing rollout time. After a small proof of concept, the group asked whether a frozen draft would become stale as RL changed the target. A 36-step smoke test initially showed little acceptance-rate drift, but a participant correctly noted that stability would be uninformative if the target weights and task performance barely changed. The author reported task improvement and then checked a larger run. [Initial result](https://marin-discord.pages.dev/#1548069487801016370/1549188136452620449); [control question](https://marin-discord.pages.dev/#1548069487801016370/1549191550867611669); [reported performance gain](https://marin-discord.pages.dev/#1548069487801016370/1549192118285893675).

In the later R2EGym run, the same frozen EAGLE-3 draft was used across 20 nodes and 60 RL updates. The reported acceptance rate did not deteriorate over those updates. The author also observed acceptance rising as target-model entropy fell, which improved rollout speed but is not necessarily desirable for the learning objective. The cautious conclusion is that this setup did not require frequent draft retraining over the tested interval; it does not prove draft stability across longer runs, other environments, or other policy changes. The channel linked the run configuration and forks for reproduction. [Run configuration](https://marin-discord.pages.dev/#1548069487801016370/1549224284004687893); [reported result and caveat](https://marin-discord.pages.dev/#1546528166086967306/1549560148320722985).
