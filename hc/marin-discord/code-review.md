## Review themes that changed research reliability

Most of this channel is review routing and PR links; a review request is not evidence that a change merged. The substantive discussions reveal recurrent failure modes across the training stack. A train/validation overlap bug could affect experiments using `num_validation_sequences`, while a contamination pipeline using a Bloom filter produced more false positives than an earlier exact n-gram method. Both cases matter because a model-quality claim can be invalidated by the data boundary even when the training code is correct. [Split bug](https://marin-discord.pages.dev/#1365058937589858324/1469912279565991966) · [Bloom-filter concern](https://marin-discord.pages.dev/#1365058937589858324/1389138919475646628).

Preemptible infrastructure drove multiple reviews. A proposed change addressed jobs dying after 24 hours when nodes were reclaimed; another returned `run_on_pod` to arbitrary nodes and used Ray's retry behavior after preemption to avoid OOM. Later PRs moved the RL pipeline toward Fray v2 and Iris, and reviews investigated an Iris scheduling bug that suppressed assignment and preemption after a deployment. The lesson is to test *recovery paths and scheduler state*, not merely a successful first launch. [Preemption lifetime](https://marin-discord.pages.dev/#1365058937589858324/1443335604946599949) · [Ray retry proposal](https://marin-discord.pages.dev/#1365058937589858324/1451678434454540358) · [RL migration](https://marin-discord.pages.dev/#1365058937589858324/1488587839921979483) · [Scheduler-state diagnosis](https://marin-discord.pages.dev/#1365058937589858324/1493490256899735582).

Model and kernel correctness was another theme. A fused cross-entropy kernel accumulated forward logits in bfloat16 while backward used float32; a correction aligned the forward accumulation type. The hero-run expert-parallel backend introduced a ragged all-to-all path with a patched PJRT wheel, making runtime pinning part of the reproducible model recipe. An inconsistent inferred sharding also caused separate XLA compilations for the first and subsequent training steps, conflicting with NCCL window registration. These are examples of precision, sharding, and runtime packaging affecting correctness beyond ordinary unit tests. [Cross-entropy precision](https://marin-discord.pages.dev/#1365058937589858324/1537532822825467964) · [All-to-all runtime](https://marin-discord.pages.dev/#1365058937589858324/1542977289451741315) · [Sharding/NCCL issue](https://marin-discord.pages.dev/#1365058937589858324/1546945120195051700).

Reviewers also discussed how to preserve experimental knowledge without freezing every historical script. A small set of live examples can serve as API tests: for instance, keep a runnable pattern for training a scaling ladder and using it to choose a bigger run, rather than preserving Delphi only as an immutable old experiment. Long-running agent research was proposed to use a branch, experiment issue, append-only logbook, and tagged snapshots so trial results remain inspectable.
