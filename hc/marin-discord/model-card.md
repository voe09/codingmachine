## A model card needs computable provenance

The team wanted a model card to state the training-data cutoff and the source and license of each dataset. The suggested cutoff calculation was to record a date for each component dataset and take the latest date; in practice the dates were not all known, so a July 2024 cutoff based on Nemotron-CC and arXiv was discussed only with **moderate confidence**. The learning here is that a model-wide date cannot be made precise after the fact if component metadata was never recorded. [Per-dataset cutoff idea](https://marin-discord.pages.dev/#1372561506327330826/1372561868043849728) · [Tentative date](https://marin-discord.pages.dev/#1372561506327330826/1372601963828744242).

Licenses were another provenance field the group wanted next to dataset definitions, not merely pasted into one release document. Hugging Face's dataset API was suggested as a source of license metadata; the browser or experiment page could then link back to it instead of relying on manually copied text. That is a design proposal, not a claim that all licenses were programmatically captured. [Metadata near dataset code](https://marin-discord.pages.dev/#1372561506327330826/1372562150496796804) · [API proposal](https://marin-discord.pages.dev/#1372561506327330826/1372608568766894182) · [Experiment-level visibility](https://marin-discord.pages.dev/#1372561506327330826/1372620894018469908).

Cards for both the base and SFT checkpoints went live, but the instruct card initially reused much of the base text and still had an evaluation-comparison TODO. The team considered these stages of one model lineage, yet separate hosted cards still had to describe their own training and results accurately. A repository-owned card was proposed as the reviewable source, but synchronization to Hugging Face was manual in this discussion, risking drift when numbers changed.
