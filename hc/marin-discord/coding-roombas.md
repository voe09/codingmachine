## Making experiments executable by contributors and agents

“Coding roombas” meant agents that perform bounded Marin development tasks, distinct from training RL agents themselves. Dataset onboarding was proposed as an early target because it has concrete stages: inspect source schema and splits, identify text fields, transform to canonical text where needed, estimate compressed size and token counts, add a dataset definition, then run a small ablation. That last check matters: successful tokenization does not establish the data's training value. [Dataset workflow](https://marin-discord.pages.dev/#1398059803980333168/1398064103230148649).

A second thread asked how a maintainer could trigger a reviewed experiment from a GitHub PR without granting broad cluster access to every contributor or agent. One proposed workflow would accept a command such as `@marin run`, launch or stop Ray jobs, and eventually report status and links to experiment results. The intended control boundary was a dry run and cost estimate in the PR, human approval, then a full run with results added to the related issue. A first workflow PR was shared, but the public-bot design remained unresolved and work was paused; the archive does not show a completed general-purpose public run bot.
