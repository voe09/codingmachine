## Make a training run explainable

The browser's “execution” view was intended to make a training run readable like an experiment in a paper: source datasets and mixture weights, architecture, initialization, optimizer and schedule, and token count derived from steps, batch size, and sequence length. The discussion pointed out that a single training stage can itself have a curriculum, so a stage-level display must not erase within-stage data changes. The executor DAG also contained the entire ancestral history of a small post-training run; collapsing, rather than deleting, earlier steps was proposed to retain provenance without overwhelming the reader. These were design goals discussed while the new view was being deployed, not a verified inventory of everything the current UI displays. [Run fields](https://marin-discord.pages.dev/#1373325310044405834/1373357560324686035) · [Curriculum caveat](https://marin-discord.pages.dev/#1373325310044405834/1373375092775583945) · [Collapse proposal](https://marin-discord.pages.dev/#1373325310044405834/1373375453359771728).

An immediate provenance test was to search a displayed experiment JSON for `gs://` paths **not listed as declared dependencies**. Some paths were embedded inside tokenized data-source settings, while older Dolma work predated the executor framework. A browser that displays an attractive DAG but misses such source paths gives researchers an incomplete account of what data reached a model. The team also considered viewing locally generated experiment JSON if hosted at a public URL, while recognizing that accepting arbitrary URLs creates security questions. ## Browsing is not search or unrestricted data export

A researcher wanted text search over JSONL to verify that n-gram-overlap hits really contained a test question. The browser was not designed for this: it scanned linearly from the start to a requested offset, so deep offsets could become slow or fail. The team limited large-file downloads and viewing to 100 entries per file, both to keep the stateless web service from being overwhelmed and to avoid accidentally serving a gated dataset. That made the browser useful for spot checks, not a substitute for indexed search or a comprehensive contamination audit. The stated 10 MB download limit and 100-entry cap were reported after deployment, but the channel did not contain a security audit. [Contamination use case](https://marin-discord.pages.dev/#1373325310044405834/1373539487669555200) · [Linear scan](https://marin-discord.pages.dev/#1373325310044405834/1373543014051352576) · [Access concern](https://marin-discord.pages.dev/#1373325310044405834/1373801274038026271) · [Reported limits](https://marin-discord.pages.dev/#1373325310044405834/1373826599132074006).

## Reliability of the evidence interface

Small UI and serialization defects had research consequences. Navigating from the home page sometimes left the browser URL unchanged, making a particular dataset view hard to cite; starting from a path URL behaved differently. The suspected cause was route-change messaging between the embedded app and its parent page, and a workaround was proposed, but this discussion does not verify a durable fix. A separate JSON response containing `NaN` made the client silently return a string instead of parsed JSON. Both failures could make a run appear uninspectable or unlinkable even when the underlying artifacts existed. [Reproduced URL behavior](https://marin-discord.pages.dev/#1373325310044405834/1375875140994334810) · [Route-message hypothesis](https://marin-discord.pages.dev/#1373325310044405834/1375886597215752273) · [NaN parsing](https://marin-discord.pages.dev/#1373325310044405834/1375864753150365736).

Later reports exposed another distinction: a region could be named in the GCP configuration but still deny the browser access, and an executor-DAG status view displayed red failure markers even for successful steps. A contributor pointed to a code fix for the latter and thought a restart was needed. The channel subsequently reports a redeployment, but not an end-to-end recheck of every earlier defect. For readers learning from experiment traces, browser presentation should be treated as a view onto artifacts, not the authoritative result itself.
