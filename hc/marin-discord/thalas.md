## A checkpoint can be ready before its training run finishes

The executor's ordinary dependency rule was “upstream Ray function finished.” That was too coarse for a long training run whose earlier checkpoints could already support downstream work. The proposed **artifact publishing** abstraction would let a producer seal a checkpoint subdirectory and signal that it was ready while the parent run continued. A concrete use was to fork periodic cooldown runs and evaluations from checkpoints of one main run; scaling-law experiments could use the same pattern. Existing “pseudodependencies” were acknowledged as a quick workaround, not a full published-artifact protocol. [Proposal](https://marin-discord.pages.dev/#1415061162701361242/1415062537678098440) · [Cooldown/eval use case](https://marin-discord.pages.dev/#1415061162701361242/1415064020087607297) · [Pseudodependency limitation](https://marin-discord.pages.dev/#1415061162701361242/1415062932576014458).

The hard part was preserving dependency semantics when a partial artifact, rather than a completed function, makes downstream work runnable. One suggestion was a watcher Ray function that finishes once the subdirectory is published. More broadly, contributors wanted the system to represent both the experiment DAG and **changes to that DAG over time**, while reusing cached artifacts only when the producing code and inputs were compatible. A Spark-inspired `cached(path)` idea illustrated this but also raised the need to track the code version that created an artifact. These were design ideas, not a confirmed Thalas implementation. [Readiness problem](https://marin-discord.pages.dev/#1415061162701361242/1415064402826100917) · [Watcher suggestion](https://marin-discord.pages.dev/#1415061162701361242/1415066212353708123) · [DAG history](https://marin-discord.pages.dev/#1415061162701361242/1415063639626485760) · [Cache provenance](https://marin-discord.pages.dev/#1415061162701361242/1415101898603757699).

For the immediate Thalas integration, the group identified CI unit tests coupled to GCP, a dry run, an integration test, and preservation of Marin's experiment hash codes as gates. Hash changes could silently invalidate cached-work reuse or trigger recomputation across the graph; a proposed check was to compare dry-run recomputation before and after the integration. The channel records a landed Thalas PR and an updated Marin PR but not a completed validation of all these gates.
